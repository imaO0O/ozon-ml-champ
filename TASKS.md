# Ближайшие задачи: три параллельных трека

Состояние на 11.08.2026. Лучшее решение — `submissions/lgbm_ens_shift_scale.csv`,
public RMSLE **1.6533490**. Наивный baseline организаторов — 2.195.

Перед началом обязательно прочитайте в [PLAN.md](PLAN.md) разделы **2 (как мерить)**
и **4 (что проверено и не работает)**. Половина очевидных идей там уже закрыта
с числами — не тратьте на них время.

## Что даёт результат, а что нет — по факту измерений

| источник улучшения | что дал |
|---|---|
| калибровка зондами лидерборда | **0.0031** |
| ансамбль 5 конфигураций | 0.0014 на валидации, −0.0004 на public |
| блок признаков `unit` | 0.0005 на одиночной модели, 0 в ансамбле |
| гиперпараметры | 0 (не переносится) |

Вывод для планирования: **моделирование на CPU упёрлось в потолок**, дальше
крупные эффекты возможны только от принципиально другого класса моделей
(нейросеть) или от калибровки, которая меряется лидербордом.

## Трек A — ноутбук, CPU: калибровка, сабмиты, сборка

Владелец файлов: `src/probe_shift.py`, `src/predict.py`, `submissions/`.

**A1. Завершить зонд кривизны.** Отправить `probe_quad_002.csv`, взять RMSLE,
посчитать оптимальный коэффициент:

```bash
python -u src/probe_shift.py --solve --gamma 0.02 --var-g 7.79935 --mse0 1.6533489803 --mse1 <ответ>
```

Если выигрыш больше 0.0005 — собрать версию с оптимальным γ и отправить.

**A2. Перемерять поправки при смене модели.** Сдвиг +0.0578 и растяжение 1.0545
измерены **для текущей модели**. Как только треки B или C дадут новую, поправки
надо получить заново: два зонда, два сабмита, полдня. Не переносите старые числа
на новую модель — они к ней не относятся.

**A3. Собрать вторую финальную кандидатуру.** Для финала нужны два **непохожих**
решения; пара с корреляцией 0.9997 уже проверена и не дала ничего. Кандидат —
ветка на CatBoost:

```bash
python -u src/train.py --cutoffs 6 --ensemble --final --name cat_ens   # состав mixed в ensemble.py
python -u src/predict.py --name cat_ens
```

затем свои зонды уровня и размаха для неё.

**A4. Вести бюджет сабмитов.** Пять в день на всю команду. Приоритет: зонды
калибровки (дают точный ответ и окупаются сразу), затем проверенные на двух
срезах улучшения. На проверку моделей с разницей меньше 0.002 сабмиты не тратить —
лидерборд на них не отвечает.

## Трек B — ноутбук, CPU: новая информация и материалы жюри

Владелец файлов: `src/features/<свой модуль>.py`, документация.

**B1. Блок признаков «форма недавнего поведения».** Все существующие признаки —
сглаженные оконные суммы. Явные векторы последних 14 дней (GMV, заказы, поиски
по каждому дню отдельно) дают деревьям то, чего в суммах нет: форму, а не объём.
Это единственная непроверенная идея в признаках с внятным механизмом.

Как проверять — обязательно по правилу двух срезов:

```bash
python -u src/train.py --cutoffs 6 --blocks windows,lifetime,ratios,platform,unit
python -u src/train.py --cutoffs 6 --blocks windows,lifetime,ratios,platform,unit,shape
python -u src/train.py --cutoffs 7 --val-cutoff 2025-12-16 --blocks ...   # то же самое на втором срезе
```

Принимать только при положительном знаке на обоих срезах.

**B2. Линейная модель как участник ансамбля.** Ridge на логарифмах признаков —
принципиально другой класс, обучается минуты, ошибается иначе, чем деревья.
Для ансамбля важна именно непохожесть, а не сила: CatBoost был равен LightGBM
по качеству и потому почти ничего не добавил.

**B3. Материалы для жюри.** Это не побочная работа: топ-15 сдают репозитории,
и оцениваются качество работы с данными, ресурсоёмкость и новизна.

* воспроизводимость с нуля по README на чистой машине — проверить руками;
* tie-breakers: Gini по предсказаниям и RMSPE суммарного GMV — свести в таблицу
  (`src/calibrate.py` уже считает второе);
* черновик питча: постановка, валидация, измерение сдвига уровня зондами,
  честный разбор отрицательных результатов.

## Трек C — ПК с видеокартой: нейросеть и третье семейство

Владелец файлов: новый модуль, существующих не трогает.

**C1. Нейросеть на последовательностях — главный неиспользованный рычаг.**
Организаторы прямо намекают на токенизацию дневного поведения. Практичный путь:
последовательность дневных событий пользователя → GRU или небольшой трансформер
→ предсказание таргета. Скрытое состояние дополнительно отдать бустингу как
признаки — часто это работает лучше, чем сама сеть.

Ожидаемый эффект — единственный, что заведомо крупнее порога измеримости.
Данные готовы: `data/raw/train.parquet`, срезы и таргеты строятся
`src/datasets.py`, протокол валидации описан в PLAN.md разделе 2.

**C2. XGBoost на GPU** как третий участник ансамбля:

```bash
pip install xgboost
python -u src/train.py --model xgb --device gpu --cutoffs 6
```

Для карт 50-й серии нужен билд под CUDA 12.8+.

**C3. Тяжёлый перебор** для нейросети — на CPU он невозможен, на GPU это часы.

## Общие правила

* **Порог 0.002.** Эффект меньше — проверять на двух валидационных срезах
  (2026-01-15 и 2025-12-16) и принимать только при положительном знаке на обоих.
* **Один эксперимент — одна ветка и один PR**, в описании строки из
  `models/experiments.csv` до и после.
* **Журналы обязательны.** `train.py` и `predict.py` пишут их сами; после ответа
  лидерборда впишите `lb_score` руками в `submissions/log.csv`.
* **Не трогайте чужие файлы.** Признаки разложены на блоки именно для этого:
  свой модуль плюс одна строка импорта в `src/features/__init__.py`.
* **Данные и веса в git не кладём** — только код и журналы.

## Чего не делать — уже проверено и закрыто

Шаг срезов 14 дней (хуже на 0.0075), взвешивание срезов по свежести,
перебор гиперпараметров LightGBM (не переносится между срезами), CatBoost
в рабочем ансамбле (ниже порога), модель остатка через `init_score`,
признак «GMV в это же окно год назад» (в данных нет 2024 года), праздничные
признаки (праздников в логе нет вообще).

Детали с числами — [PLAN.md](PLAN.md), раздел 4.

## Ритм

Раз в день сводим: кто что померил, какие строки появились в журналах, кто
тратит сабмиты завтра. Решения принимаем по валидации на двух срезах, а не
по public — на нём 50 000 клиентов из 250 000, и разброс между случайными
половинами такого размера составляет 0.007 RMSLE, что больше любого нашего
эффекта.
