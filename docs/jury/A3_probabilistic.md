# A3. Вероятностная иерархическая модель

Отвечает на два свойства решения, названные организаторами отдельно: чтобы
модель была **вероятностной** и учитывала **иерархическую структуру задачи**.

Реализация — `src/btyd.py`, запускается одной командой:

```bash
python -u src/btyd.py --cutoff 2026-01-15
```

## Чего не умеет наше основное решение

Бустинг и нейросеть выдают **точку** — условное среднее `log1p(GMV)`. Этого
достаточно для RMSLE и ни для чего больше. На вопросы «купит ли этот клиент
вообще», «не ушёл ли он», «каков разброс его чека», «сколько выручки под риском»
точечная модель не отвечает не потому, что плохо обучена, а потому, что таких
величин у неё нет.

Мы добавили модель, у которой они есть по построению.

## BG/NBD + Gamma-Gamma: порождающая модель поведения

Это не регрессия, а описание того, **как клиент себя ведёт**:

* пока клиент «жив», он покупает по пуассоновскому процессу с личной
  интенсивностью λ;
* после каждой покупки с вероятностью `p` он уходит навсегда;
* λ по популяции распределена как `Gamma(r, α)`, `p` — как `Beta(a, b)`;
* размер чека — `Gamma`, её параметры тоже общие для популяции (Gamma-Gamma).

**Последние две строки и делают модель иерархической.** У каждого клиента свои
λ и `p`, но они не свободны: они порождены общим распределением. Клиент с двумя
покупками не получает наивную оценку `λ = 2/T` — он **стягивается к популяции**
тем сильнее, чем меньше о нём известно.

Тот же механизм виден в формуле ожидаемого чека явно:

    E[чек] = w · (личное среднее) + (1 − w) · (популяционное),   w = p·x / (p·x + q − 1)

Вес личного среднего растёт с числом покупок `x`. У клиента с одной покупкой
оценка почти популяционная, у клиента с двадцатью — почти собственная. Это
partial pooling в чистом виде, и он не подобран, а выведен из правдоподобия.

**Оценённые параметры** на срезе 2026-01-15 (максимум правдоподобия, 216 058
клиентов с историей покупок):

| | значение |
|---|---|
| BG/NBD | r = 1.084, α = 17.69, a = 0.014, b = 3.703 |
| Gamma-Gamma | p = 1.254, q = 3.131, γ = 92.76 |
| популяционный чек | 54.58 |

## На какие вопросы она отвечает из коробки

На каждого клиента модель отдаёт пять величин: `p_alive`, `e_trans`,
`e_value`, `e_gmv`, `p_zero`. Отсюда прямо считаются ответы, которых
из бустинга не получить:

| вопрос | ответ на срезе 2026-01-15 |
|---|---|
| сколько клиентов вероятно ушли, `P(жив) < 0.2` | 1 140 человек, 0.5% базы |
| сколько выручки под риском, `P(жив)` от 0.2 до 0.6 | 1 908 клиентов, ожидаемый GMV 43 957 |
| кто принесёт больше двух покупок за окно | 66 079 клиентов (30.6%), GMV 15.0 млн |
| доля ожидаемого GMV в верхнем дециле | 45.1% |

**Содержательный вывод из первой строки:** отток в этих данных почти
не выражен — 97.5% клиентов модель считает живыми. Это факт о датасете,
а не о модели: площадка росла весь период, и «уход навсегда» здесь редкое
событие. Для решения это означает, что механизм выживания даёт мало, и мы
не стали строить на нём предсказание.

## Вероятности откалиброваны — ответы можно использовать

Предсказанная вероятность покупки против фактической доли купивших, срез
2026-01-15:

| P(покупка) предсказано | фактически | клиентов |
|---|---|---|
| 0.132 | 0.187 | 13 899 |
| 0.305 | 0.297 | 31 520 |
| 0.503 | 0.442 | 39 694 |
| 0.704 | 0.621 | 47 137 |
| 0.926 | 0.874 | 83 808 |

Порядок соблюдён везде, в средних корзинах попадание близкое. В верхних
корзинах модель **самоуверенна** на 5–8 процентных пунктов — это надо называть
прямо: пуассоновское предположение переоценивает регулярность самых активных
клиентов. Для ранжирования и для оценок «сколько под риском» этого достаточно,
для точечного предсказания — нет, и мы его для этого не используем.

## Честный учёт: почему её нет в сабмите

| модель | выровненный RMSLE | Gini |
|---|---|---|
| наш ансамбль бустинга | **1.66941** | 0.7378 |
| BG/NBD + Gamma-Gamma | 1.90213 | 0.6922 |

Разрыв огромный, и он ожидаем: четыре параметра против 242 признаков. Модель
описывает **механизм**, а не подгоняется под данные, и в этом её сила
и её слабость одновременно.

**Сверх бустинга она несёт немного, но статистически бесспорно.** Регрессия
остатка выровненного ансамбля на её выходы:

| величина | t | линейный потолок |
|---|---|---|
| `p_alive` | 9.8 | +0.00032 |
| `e_trans` | 8.2 | +0.00023 |
| `log e_gmv` | 5.4 | +0.00010 |
| **все вместе** | | **+0.00054** |

Это ниже нашего порога приёмки 0.002, поэтому в рабочую модель признаки
не заведены. Но t = 9.8 означает, что сигнал реальный, а не шум: механизм
выживания несёт информацию, которой в 242 признаках нет.

## Независимая проверка оценки суммарного GMV

Побочный результат, важный для tie-breaker'а жюри. Суммарный ожидаемый GMV
по BG/NBD считается прямым суммированием `e_gmv` — без единой калибровочной
поправки, из одних параметров модели:

| источник оценки | январское окно | тестовое окно |
|---|---|---|
| факт | **21 008 510** | неизвестен до раскрытия |
| BG/NBD, сумма `e_gmv` | 22 086 565 | **21 894 184** |
| наша калибровка сабмита, ×2.002 | ≈ 20.2 млн | ≈ 20.2 млн |

На январском окне, где факт известен, порождающая модель промахивается
на **+5.1%**, а скалярная калибровка точечных предсказаний — на **−3.8%**.
Промахи **в разные стороны**, и это существенно: оценки не имеют общих
допущений, поэтому факт с высокой вероятностью лежит между ними.

**Для тестового окна отсюда следует оценка 20.2–21.9 млн**, и мы предъявляем
её именно вилкой, а не одним числом. Одна граница получена суммированием
`e_gmv` из параметров порождающей модели без единой поправки; вторая —
скалярной калибровкой суммы сабмита, проверенной на втором срезе. Совпадение
порядка при полностью разных путях вывода — сильнее любой из оценок отдельно.

Число 219 168 в тестовой строке — клиенты с историей покупок; у остальных
30 832 покупок не было ни разу, и BG/NBD к ним неприменим по построению.
Их вклад в сумму мал, но это причина, по которой оценка снизу смещена.

## Где ещё в решении используется иерархия задачи

**Двухголовая модель** — простейшая иерархия того же рода:

    E[log1p(y)] = P(покупка) · E[log1p(y) | покупка]

Разложение точное, потому что `log1p(0) = 0`. Классификатор и регрессор
обучаются раздельно, что позволяет каждому видеть свою задачу. Эта часть
входит в рабочее решение и даёт лучший Gini среди голов — 0.7383 против 0.7373
у одноголовой.

**Стекинг** — иерархия по источникам: предсказание нейросети входит признаком
в бустинг, и бустинг решает **поклиентно**, где ей верить. В отличие от бленда,
который смешивает с одним весом на всех, это условная на клиенте комбинация.
Измеренная разница: две сети внутри стекинга не вытесняют друг друга
(+0.00037 и +0.00080 на двух срезах), а внутри бленда — вытесняют.

## Что стоит сказать о подходе в целом

Мы сознательно держим два класса моделей с разным устройством ошибки.
Дискриминативная половина (бустинг, сеть) оптимизирует метрику и выигрывает
по ней. Порождающая половина (BG/NBD) метрику проигрывает, но отвечает
на вопросы бизнеса и служит независимой проверкой: её оценка суммарного GMV
получена из других допущений и сошлась с калибровочной.

Ставить в сабмит следует первую. Показывать в разборе решения нужно обе —
иначе непонятно, что именно измерено, а что предположено.
