# C3. Пакет воспроизведения трека C

Для трека B, запускающего сквозное воспроизведение на боевых данных. Все числа
здесь пересчитаны из сохранённых файлов предсказаний `models/*_valpred_*.npz`,
а не взяты из колонки журнала — см. предупреждение ниже, оно не формальность.

## Критерий приёмки

Пол измерен двойником: два прогона одной конфигурации, отличающиеся только
точностью арифметики (fp32 против bf16), тот же сид.

| срез | D двойников | RMSLE двойников | \|ΔRMSLE\| |
|---|---|---|---|
| январь | 0.00656 | 1.68193 / 1.68274 | **0.00081** |
| декабрь | 0.01966 | 1.75360 / 1.75206 | **0.00155** |

**Расхождение до 0.001 на январе и до 0.002 на декабре — воспроизведение;
больше — находка.** Округлено вверх от измеренного.

Проверка самого критерия: знак двойника переворачивается между срезами (на
январе fp32 лучше, на декабре хуже). Это подпись нулевой информации — если у
вас расхождение имеет устойчивый знак на обоих срезах, дело не в арифметике.

**Перевода D в RMSLE не существует.** Отношение ΔRMSLE к D равно 0.123 и 0.079
на двух срезах — непостоянно. D это средний квадрат расхождения двух
предсказаний, ΔRMSLE — разница их ошибок; два файла могут быть далеки по D и
равны по RMSLE. На этом стоит весь закон про направление, поэтому пол пришлось
измерять заново в других единицах, а не пересчитывать.

## Предупреждение: какую величину сверять

**Сверяйте выровненный с выровненным.** Уровень предсказаний правится на
сабмите бесплатным сдвигом, поэтому сравнивать модели между собой нужно после
выравнивания. У сетей сырая и выровненная величины расходятся до **0.02134**,
у бустинга совпадают.

Это не теория. На 86 конфигурациях январского среза:

* **29.4% пар** (1075 из 3655) упорядочены по-разному сырой и выровненной;
* корреляция рангов **0.454**;
* лучшая модель разная: `stack_y_final` по сырой, `gru_w52` по выровненной.

Смешение этих двух величин 28.08 стоило треку C ложной находки «+0.00669» —
выровненное число нового прогона сравнили с журнальным сырым старого. Разбор
в `C2`, раздел одиннадцатый.

До 28.08 `seq_train.py` писал в журнал только сырую величину, в колонку
`rmsle_blend`, по которой команда сравнивает строки. Теперь пишет обе, вторая
в колонке `rmsle_aligned`. **Строки журнала старше 28.08 в колонке
`rmsle_blend` содержат сырую величину** — для сверки их использовать нельзя,
берите числа из этого документа или пересчитывайте из `.npz`.

## Что у трека C не проверено

Сквозной путь «сырые данные → признаки → модели» с чистого клона у нас не
проходил ни разу. Честная формулировка: воспроизводимость трека C подтверждена
на уровне журнала и кода, сквозным прогоном не проверена. Это и есть то, что
вы сейчас закрываете.
