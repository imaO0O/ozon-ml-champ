## 28.08. Чувствительность аудита утечки: одно несовпадение

### Сразу о границах этой проверки

Это **не** прогон на боевых данных и не замена ему. Сверка `stk2_jan`,
`yearw`, `ev_jan`, `nostfin` с журналом требует `train.parquet` и видеокарты —
она остаётся невыполненной.

Здесь проверено другое и на синтетике: **ловит ли наш аудит утечку,
если утечка есть.** Применён принцип, который два трека нашли независимо
(`B3_pitch`, §4в): прежде чем измерять неизвестное, измерь известное
и проверь, что прибор его показывает. Аудит утечки всегда печатал
«нарушений ноль», и никто не проверял, способен ли он напечатать другое.

Стенд: `build_features` скопирован из `src/features/__init__.py` дословно
(редакция 28.08), сравнение — из `check_tabular` в `src/leak_audit.py` дословно.
Данные синтетические: 3 000 пользователей, 91 795 строк, cutoff 2026-01-15.
Затем в код по очереди подсажены четыре утечки разного вида.

### НЕСОВПАДЕНИЕ: один вид утечки проходит мимо первой проверки

| подсаженная утечка | вердикт проверки |
|---|---|
| целый код (контроль) | чисто — верно |
| фильтр `build_features` пропускает горизонт вперёд | **поймана** (3 признака разошлись) |
| агрегат считается из переданного кадра мимо `hist` | **поймана** |
| **блок читает лог сам, мимо переданного `lf`** | **НЕ ПОЙМАНА — «чисто»** |

Причина механическая. Контролем в `check_tabular` служит **обрезанный
кадр**, который передаётся аргументом. Всё, что считается из этого
аргумента, у двух рук различается и ловится. Всё, что читает лог
самостоятельно, у обеих рук одинаково — и поэтому совпадает побитово
вместе со своей утечкой.

Это не умозрительный вид: такой путь в коде есть. `build_dataset`
подключает предсказания сетей через `.net.attach`, и читаются они
из внешних файлов, а не из переданного `lf`. В комментарии к модулю
это сказано прямо: «не выражения над логом, поэтому подключаются здесь,
а не блоком реестра». То есть стекинг — именно то место, где утечка живёт
чаще всего по словам самого `leak_audit.py`, — первой проверкой не покрыто.

**Почему это не отменяет вывода аудита.** Стекинг покрыт **третьей**
проверкой — порядком срезов в журнале, и именно она ловит случай
«сеть обучалась на данных, доставших до среза». Вывод менять не надо,
надо менять формулировку. Сейчас в документах первая проверка подана как
«все 242 признака совпадают побитово» без указания, что именно это
исключает. Точная формулировка:

> Первая проверка исключает утечку через дневной лог: любой признак,
> вычисленный из переданного кадра, обязан совпасть с вычисленным
> из обрезанного. Внешние источники (предсказания сетей) проверяются
> не ею, а третьей проверкой — порядком срезов в журнале.

Дешёвая починка, если захочется закрыть и этот путь механически: вторую
руку строить не из обрезанного кадра, а из обрезанного **файла** — тогда
любое самостоятельное чтение лога тоже попадаёт под контроль.

### Совпадения того же прогона

Проверка ловит два вида из трёх подсаженных: сломанный фильтр по cutoff’у
и агрегат мимо `hist`. На целом коде даёт «чисто» — то есть не всегда
молчит и не всегда кричит.

Отдельно подтвердилось утверждение из комментария к `day_context`
(«считается только по событиям до cutoff’а, так что утечки нет»): даже
если подать в него **неотфильтрованный** кадр, результат не меняется:
соединение по `event_date` отбрасывает будущие дни само.

## 13.08. Прогон цепочки README на синтетике

Окружение: Ubuntu, пустая папка, ничего из проекта предварительно
не установлено. Боевых данных нет, поэтому цепочка пройдена на синтетике
из `make_fake_data.py` (7 887 пользователей против 250 000 в бою). Значения
RMSLE здесь не сопоставимы с журнальными и ничего не говорят о качестве.

### Главный результат

**Вся цепочка из README прошла без единой правки кода.** Ни одной ошибки
импорта, ни одного ненайденного файла, ни одного несуществующего флага.

### Закрытые вопросы по окружению

Проверено на **Python 3.12.3**; нижняя граница — 3.10 (синтаксис `X | None`).
Цепочка прошла на polars 1.43.2, lightgbm 4.7.0, numpy 2.4.4.

Для основной цепочки достаточно четырёх пакетов — polars, pyarrow, numpy,
lightgbm. `pandas`, `scikit-learn`, `matplotlib`, `tqdm` и `catboost` не
понадобились ни разу: самый тяжёлый в установке `catboost` нужен только
для составов `cat` и `mixed`.

Отсутствие git ломает прослеживаемость — подтверждено: прогон в папке
без `.git` дал `?` в колонке `commit` в обоих журналах, не сообщив об этом
ни слова.

### Два дефекта, найденных прогоном — статическим чтением не видны

Оба починены в `main`. Описание оставлено: оно показывает, что именно
нашёл прогон на чистой машине.

**1. `predict.py` падает трейсбеком вместо своего же сообщения.** Обучил
без `--final`, пошёл делать сабмит — `FileNotFoundError: models/nofinal_meta.json`.
Заготовленная вежливая проверка недостижима: файл `_meta.json` вообще
не создаётся без `--final`.

**2. `datasets.py --clean` всегда удаляет кэш с `--history`.**
`clean_stale_cache` решает по `p.stem.endswith(keep)`, а имя таких файлов
кончается на `_h180`. Продемонстрировано на одной версии признаков:
скрипт удалил свежий кэш и тут же его перестроил.

### Численная проверка ключевого утверждения B2

«Калибровка не меняет Gini» проверено на реальном векторе предсказаний
(7 887 значений, размах log1p от 0.221 до 8.329): все три поправки по
отдельности и подряд сохраняют порядок клиентов точно. Производная
поправки кривизны `1 + γ(2u − c)` при c = 1.9957 лежит в диапазоне
от 0.8627 до 1.0775 — всюду положительна. Нуля она достигла бы при u = 38.7
при наблюдаемом максимуме 6.18 — запас шестикратный.
