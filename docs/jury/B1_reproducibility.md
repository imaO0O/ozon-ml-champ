# B1. Воспроизводимость с чистой машины

Аудит по состоянию на 12.08.2026.

README пройден построчно и сверен с кодом: флаги против `argparse`, обещания
про журналы против `.gitignore`, команды из `TASKS.md` против того, что скрипты
на самом деле печатают. Фактический прогон в пустой папке ещё не делался —
пункты про версию Python, время и объём диска помечены как требующие замера.

## A. Блокеры: по README финальный файл не собирается

**A1. Третий шаг калибровки нигде не описан.** README доводит читателя до
сдвига уровня и растяжения, а кривизна не упомянута вовсе: флаг `--gamma`
в `probe_shift.py` работает и дал 0.0004 из наших 0.0035, но в README не
встречается ни разу. Посторонний человек остановится на двух поправках из трёх.

Речь именно о **процедуре**, а не о числах. Захардкоженные константы
`0.0578` и `1.0545` были убраны из README сознательно (коммит `97b23cc`):
они относятся к конкретной модели, и скопировавший их для новой модели молча
получил бы неверную калибровку. Возвращать их не нужно и вредно — нужен
третий блок процедуры рядом с двумя уже описанными.

**A2. Разбор ответа зонда кривизны недокументирован.** В README только `--solve`
с `--var-p`. Для кривизны нужны `--gamma` и `--var-g`, иначе скрипт завершится
с «для квадратичного зонда нужен --var-g». Оба флага в README отсутствуют.

**A3. Два из четырёх «обязательных» журналов в git не попадают.** README
обещает `models/experiments.csv`, `models/tuning.csv`, `models/ensemble.csv`,
`submissions/log.csv`. В `.gitignore` белый список из двух файлов: `models/*`
с исключением `experiments.csv`, `submissions/*` с исключением `log.csv`.
Проверено: в `models/` ровно один файл.

**A4. `models/calibration.txt` недостижим.** PLAN раздел 5 ссылается на него
(«Числа в models/calibration.txt»), но файл подпадает под `models/*`.

**A5. `calibrate.py --apply` неисполним после клонирования.** README и TASKS B2
предлагают `--apply submissions/<файл>.csv`, но csv-сабмиты не коммитятся —
в папке только `log.csv`. Нужен полный цикл `datasets.py` → `train.py --final`
→ `predict.py` перед этой командой.

## C. Окружение: числа у жюри не совпадут

**C1. Версия Python не указана нигде.** Требует замера.

**C2. В `requirements.txt` только нижние границы.** Другая минорная версия
LightGBM сдвигает точку ранней остановки, а с ней RMSLE — при пороге
различимости 0.002 это существенно. Нужен `pip freeze` в
`requirements.lock.txt`; текущий файл оставить как есть.

**C3. Требования по диску — замерено, расхождение снято.** На боевых данных:
сырые данные **178.3 МБ**, кэш признаков **91.8 МБ на срез**, то есть
**642.8 МБ на семь срезов** одной версии признаков (замер на версии `f30857f2`
с признаками сети). Прежние оценки «~360 МБ» в `datasets.py` и «~400 МБ»
в PLAN обе занижены — они относятся к версии до блоков `unit` и `ranks`
и до признаков сети. Планировать надо **около 1 ГБ на версию признаков**,
а версий на диске обычно две-три сразу.

**C4. Скачивание архивом ломает колонку `commit`.** `utils.git_commit()` при
неудаче возвращает `"?"` — падения нет, но хеша в журналах не будет. Нужна
явная строка про `git clone`.

## D. Мелочи, на которых можно споткнуться

**D1. Абсолютный путь в `calibrate.py --apply` ломается на Windows.** Проверка
`startswith(("/", "C:"))` не ловит диски `D:`, `E:` — путь склеится с корнем
репозитория. Относительный путь работает всегда.

**D2. `calibrate.py` — не быстрая справочная команда:** перед применением
поправки он обучает две модели (январь и декабрь) с `--rounds 20000`.

**D3. Множитель измеряется не на той модели, к которой применяется.**
`calibrate.py` учит одиночную конфигурацию `BASE_PARAMS`, а множитель умножает
предсказания ансамблевого откалиброванного сабмита. Дополнение к оговорке PLAN
про двойной учёт: там про поправки, здесь про то, что и модель другая.
Число 21.4 млн подавать жюри как оценку сверху с обеими оговорками.

**D4. Gini по сабмиту не считается в принципе:** `metrics.gini_norm` требует
истины, а для тестового окна её нет; `calibrate.py` Gini не печатает. В TASKS
задача B2 сформулирована так, будто оба tie-breaker'а берутся одной командой.
Источник Gini — только валидация: `gini_blend` в `experiments.csv` и
`val_gini` в `log.csv`.

## Чек-лист прогона на чистой машине

Выполнять в пустой папке, фиксируя факт, а не ожидание.

1. `git clone` в пустую папку — сработало ли, размер клона.
2. Окружение и `pip install -r requirements.txt` — версия Python, полный
   `pip freeze`, время, ошибки сборки колёс.
3. Данные в `data/raw/`, проверить что папка создаётся сама при импорте
   `config.py`.
4. `python -u src/datasets.py --test` — время, размер `data/processed/`,
   строки и колонки по срезам.
5. `python -u src/train.py --cutoffs 6 --ensemble --final --name lgbm_ens` —
   время, `rmsle_blend`, `gini_blend`, итерации. Сравнить со строкой журнала
   `lgbm_ens` (1.68402 / 0.7378); расхождение должно уложиться в 0.001.
6. `python -u src/predict.py --name lgbm_ens` — сумма, доля нулей, имя файла.
7. `python -u src/probe_shift.py --derive-shift --source <файл>.csv` — сверить
   выведенный сдвиг с +0.0578.
8. Пройти растяжение и кривизну по процедуре из PLAN раздела 3 и убедиться,
   что третий шаг вообще выполним по README. Сумма итогового файла для
   `lgbm_ens_full_calib.csv` равна 10 063 305 — ориентир, если цепочка
   пройдена на той же модели.
9. `python -u src/calibrate.py --apply submissions/<файл>.csv` — время и три
   суммы из вывода.
10. Отдельно: прогнать синтетику через `make_fake_data.py` до конца цепочки.

Всё, что пришлось додумать или подсмотреть в коде, — дописать в README.

## Что дописать в README

**В «Установка»:** требуемая версия Python; клонировать через `git clone`,
а не архивом, иначе колонка `commit` в журналах будет пустой; объём диска и
время полного прогона; ссылка на `requirements.lock.txt` с точными версиями,
на которых получены числа журналов.

**В «Запуск»:** добавить третий шаг калибровки рядом с двумя описанными, тем
же процедурным стилем и без констант:

```bash
python -u src/probe_shift.py --source base.csv --gamma 0.005 --out probe_q.csv
python -u src/probe_shift.py --solve --gamma 0.005 --var-g <из вывода> --mse0 <RMSLE базы> --mse1 <RMSLE зонда>
```

Рядом — строка о том, что кривизна применяется к файлу, у которого уже
поправлены уровень и размах, и что шаг зонда берётся малым: направление
заранее не угадывается, а цена ошибки растёт как квадрат шага (зонд с шагом
0.02 стоил 0.0022 RMSLE, с шагом 0.005 стоил бы около 0.0001).

**В «Работа в команде»:** исправить список журналов на фактический — в git
лежат `models/experiments.csv` и `submissions/log.csv`, остальное содержимое
`models/` и `submissions/` не коммитится.

**В раздел про калибровку:** `calibrate.py` обучает две модели заново, это
полноценный прогон; путь задавать относительно корня репозитория.
