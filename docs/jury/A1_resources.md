# A1. Ресурсоёмкость решения

Оценивается жюри отдельным критерием. Все числа ниже — замеренные, не оценочные.

## Железо

Бустинговая половина решения целиком построена на **ноутбуке без дискретной
видеокарты**: 16 логических ядер, 13.7 ГБ оперативной памяти, AMD Radeon
integrated. Нейросетевая половина обучалась на RTX 5060/5070.

С 20.08 обе половины воспроизводятся на одной машине — Ryzen 5 7500F,
32 ГБ, **RTX 5070 12 ГБ**. Это ничего не меняет в требованиях: бустинг
по-прежнему не нуждается в видеокарте, сеть по-прежнему нуждается.

CatBoost, вопреки распространённому ожиданию, видеокарты здесь тоже не
потребовал: 459 итераций за 2.9 минуты на CPU (0.38 с на итерацию) при качестве
1.68632 против 1.68612 у LightGBM — то есть модели равны.

## Стоимость полного воспроизведения

| шаг | время |
|---|---|
| сборка признаков, 7 срезов по 30.6 млн строк | 1.5–2.5 мин |
| обучение ансамбля из 5 конфигураций + двухголовая модель | 28 мин |
| то же со смешанным составом (+2 CatBoost) | 46 мин |
| сборка сабмита на 250 000 клиентов | 30 с |
| калибровка (три поправки) | секунды |
| дневная матрица 250 000 × 409 × 18 для сети | 39 с, 3.4 ГБ на диске |
| сеть с распределительной головой, один сид | 17 с на эпоху, 20 эпох ≈ 6 мин |
| OOF сети по 7 срезам × 3 сида для стекинга | 2 ч 10 мин |
| обучение стекинга (ансамбль + признак сети) | 20–25 мин |

**Бустинговая половина воспроизводится с нуля примерно за полчаса** на обычном
ноутбуке. Пиковая память при обучении — 3.5 ГБ из 13.7, то есть с большим запасом.

Нейросетевая половина требует видеокарты: сидов не меньше трёх, потому что
одиночный прогон сети не меряет ничего на уровне тысячных (PLAN.md, раздел 2).
Полный состав из четырёх участников — примерно час на RTX 5060.

**Самая дорогая часть решения — не обучение, а OOF для стекинга:** 2 часа
10 минут на 21 прогон. Дешевле не выходит по существу, а не по нерадивости:
предсказание для каждого среза обязано быть получено сетью, которая этот срез
не видела, иначе бустинг выучит утечку. Это цена честного стекинга, и она
платится один раз на сеть.

Загрузка видеокарты при обучении сети — 15%: узкое место не вычисления,
а чтение окон из матрицы. То есть более мощная карта решение не ускорит,
а более быстрый диск ускорит.

## Почему сборка признаков занимает минуты, а не часы

Лог прорежен: строки есть только за дни с активностью. Полная сетка
`user × day` — это около 100 млн строк, и её разворачивание, о котором прямо
предупреждают организаторы, съело бы всю память.

Мы её не разворачиваем ни разу. Все оконные агрегаты за 7/14/30/60/90/180/365
дней считаются **одним ленивым `group_by` в polars** с фильтрами внутри
агрегации. Отсюда 10–37 секунд на срез вместо десятков минут.

## Совокупные затраты за всю работу

| | |
|---|---|
| суммарное время одиночных прогонов | 91 мин (медиана 2.0 мин) |
| сырые данные | 178.3 МБ |
| кэш признаков | 91.8 МБ на срез, 642.8 МБ на одну версию (7 срезов) |
| дневная матрица для сети | 3.4 ГБ |
| кэш признаков со стекингом (на набор сетей) | ещё около 700 МБ |
| веса моделей | 184 МБ |
| код решения | 45 файлов |
| сабмитов израсходовано | **47** из ~95 доступных за этап |

Из 47 сабмитов **14 — калибровочные зонды**, и именно они дали основной прирост.
Это к вопросу об эффективности расходования попыток: треть бюджета за всё время,
и потрачены они на измерения, а не на перебор догадок.

**Одно семейство зондов отменено целиком.** Растяжение больше не измеряется
на лидерборде: оптимальное α считается офлайн из целевой дисперсии,
`α* = sqrt(2.6408 / Var(log1p(предсказание)))`. Правило выведено на шести
измеренных значениях α от 1.0122 до 1.0572 и проверено предсказанием,
записанным до ответа: предсказывали 1.0507, зонд решил 1.0507 (PLAN.md,
раздел 3). Новая модель теперь стоит **одного** сабмита вместо трёх.

**Два зонда не стоили ничего вовсе** — они улучшили результат уже
в момент измерения: зонд кривизны дал 1.6495379 против базы 1.6495493, зонд
вдоль признака 1.6495407 против той же базы. Это следствие правила брать малый
шаг: при верно угаданном направлении зонд платит сам за себя, а его ответ
всё равно даёт точный оптимум.

Отдельно стоит отметить, чего сабмиты **не** стоили. Результат любой комбинации
уже отправленных файлов вычисляется из их же public-оценок аналитически
(`src/blend_opt.py`): пять проверок бленда финалистов не потребовали ни одной
попытки. Сравнения моделей с разницей на валидации меньше 0.002 мы на лидерборд
не выносим вовсе — он на такую разницу не отвечает, это проверено (разница
0.0014 обернулась на public −0.0004, то есть знаком в другую сторону).

## Что позволило не жечь ресурсы впустую

**Кэш признаков привязан к хешу кода.** Изменил блок признаков — пересборка
происходит сама; не изменил — переиспользуется готовое. Без этого сокомандник,
добавивший признак, молча обучился бы на старом кэше и выбросил рабочую идею.

Хеш нормализует переводы строк: иначе `git checkout` на Windows менял бы его
на пустом месте, а у участников с разными настройками `autocrlf` он различался
бы при одинаковом коде.

**Порог измеримости определён экспериментально** (PLAN.md, раздел 2): 0.002
между валидационными срезами и 0.0009 между пересборками кэша. Всё, что мельче,
проверять бессмысленно — это правило сэкономило команде десятки прогонов.

**Отрицательные результаты задокументированы с числами** — двадцать
направлений, каждое с воспроизводимым замером. Их ценность в том, что никто из команды не проверял их дважды.

## Мы измерили собственную сложность и она оказалась избыточной

Отдельный результат, который стоит предъявить прямо: **рабочая схема стоит семь
обучений вместо одного, и разница между ними лежит внутри нашего же порога
измеримости.**

| часть схемы | цена | что даёт |
|---|---|---|
| ансамбль 5 конфигураций вместо одной | ×5 обучений | +0.00084 на валидации (порог 0.0009), **−0.0004 на лидерборде** |
| двухголовая модель поверх одноголовой | +2 обучения | 0.0001–0.0003 на последних моделях |

Выигрыш двухголовой части не превышал 0.0007 ни разу за всю работу, а вес
бленда между головами скачет от 0.2 до 0.9 — признак подгонки под шум
на плоской кривой, а не устойчивого параметра.

Почему это не убрано. Двухголовая часть оставлена не ради RMSLE, а ради
**tie-breaker'а жюри**: у неё лучший Gini среди голов, 0.7383 против 0.7373
у одноголовой. Ансамбль оставлен по инерции, и честный вывод такой: **одна
конфигурация даёт тот же результат в семь раз дешевле.** Полное воспроизведение
упрощённой схемы — около четырёх минут вместо получаса.

Мы приводим это сами, потому что таких ревизий обычно не делают: решение
об ансамбле принималось, когда модель была слабее, и с тех пор ни разу
не перемерялось. Перемеряли — и оно не подтвердилось.
